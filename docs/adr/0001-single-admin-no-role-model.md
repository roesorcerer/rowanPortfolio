# Single-admin authentication; no role model

The portfolio site authenticates exactly one principal — the site owner — who can manage Projects, read Messages, and view the analytics dashboard. Anyone else is an anonymous **Visitor**. We deliberately rejected the latent multi-user / role-based shape inherited from the MERN template: the `User` model and its `role: "admin" | "user"` enum existed in code but no `"user"` role was ever reachable in practice, the `requireAdmin` middleware was the only branch on role anywhere, and the `AuthUser.role` JWT type had already drifted to `string` (looser than the model's enum) without anyone noticing. Keeping unused role infrastructure cost ongoing friction (two type definitions to keep in sync, an obvious "is this used?" question for any new reader) and bought nothing concrete; the `User` model has been renamed to **Admin**, the `role` field removed, and the `requireAdmin` middleware collapsed into `requireAuth`. If a second principal is ever genuinely needed — a collaborator with scoped access, for example — that is the moment to reintroduce roles (or capability tokens), not before.
